01 / Project overview

Follow the evidence

The goal was to practise a repeatable assessment workflow and explain the security lessons clearly, without publishing an active machine solution.

Project contribution

  • Performed network and web application enumeration in the authorized lab.
  • Investigated application behavior and server-side input handling.
  • Practised Linux host enumeration and privilege-escalation analysis.
  • Recorded observations and considered remediation and monitoring opportunities.

Environment & tools

  • Hack The Box Labs with Kali Linux in VirtualBox.
  • HTB Machines VPN for lab connectivity.
  • Nmap, Gobuster, curl, sqlmap and Netcat.
  • Tool versions are retained in the project notes where they were captured.
02 / Assessment method

A practical, repeatable workflow

Each phase builds on observations from the previous one. The public summary describes the learning process without exposing machine-specific steps.

03 / Defensive perspective

Turn observations into safeguards

These are general security themes and monitoring ideas considered during the project. They are not claims of deployed or validated detections.

Prevention & hardening

  • Apply least privilege to application, database and system services.
  • Validate structured input server-side and use strict parsers.
  • Avoid unsafe shell execution and protect sensitive configuration files.
  • Isolate restricted or kiosk-style sessions from privileged operations.

Monitoring opportunities

  • Review anomalous application requests and repeated input-validation failures.
  • Alert on unexpected child processes launched by application services.
  • Investigate unusual activity in restricted user sessions.
  • Monitor sensitive file changes followed by service or automation changes.

Monitoring items are hypotheses for further validation. No Sentinel alert or SIEM rule deployment is claimed for this project.
